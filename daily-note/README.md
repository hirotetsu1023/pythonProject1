# デイリーノート自動生成 (GAS)

毎晩21時に、その日のノート `YYYY-MM-DD.md` を生成して Google Drive に保存します。

消えてしまった元スクリプトの再構築版です。出力フォーマットは実物の
`2026-07-30.md` / `2026-07-31.md` に合わせてあります。

## データの流れ

```
iPhone カレンダー ─┐
                   ├─ iOS ショートカット ─(メール)─▶ Gmail ─┐
iPhone リマインダー ─┘                                        ├─▶ GAS (毎晩21時) ─▶ Drive に .md
                                          Gmail(当日の受信) ─┘         └ Claude で仕分け
```

iCloud カレンダーを**公開せず**に済ませるため、予定もリマインダーも
iOS ショートカット経由でメールとして送り、GAS がそれを読みます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `Code.gs` | 本体（ブリッジ解析・Gmail 取得・Claude 呼び出し・Markdown 生成・Drive 保存） |
| `appsscript.json` | マニフェスト（OAuth スコープ） |

## セットアップ

### 1. GAS プロジェクトを作る

`script.google.com` で新規プロジェクトを作り、`Code.gs` と `appsscript.json` を貼り付けます。

### 2. Claude API キーを登録

「プロジェクトの設定」→「スクリプト プロパティ」で追加します。

| プロパティ | 値 |
| --- | --- |
| `ANTHROPIC_API_KEY` | `sk-ant-...` |

未設定でもノート自体は生成されます（「今日のひとこと」とメール仕分けが空になるだけ）。

### 3. iOS ショートカットを作る

iPhone の「ショートカット」アプリで新規作成し、以下を並べます。

1. **カレンダーの予定を検索** … 期間「今日」→ 変数 `今日の予定` に保存
2. **カレンダーの予定を検索** … 期間「今後14日」→ 変数 `今後の予定` に保存
3. **リマインダーを検索** … 「完了していない」→ 変数 `リマインダー` に保存
4. **テキスト** … 下記の内容（変数を差し込む）

```
[CAL]
（変数：今日の予定）
[CALNEXT]
（変数：今後の予定）
[REM]
（変数：リマインダー）
```

5. **メールを送信** … 宛先＝自分、件名＝`DAILY-BRIDGE`、本文＝手順4のテキスト、「送信前に表示」はオフ

最後に「オートメーション」で **毎日 20:50** にこのショートカットを実行するよう設定します
（GAS が21時に読むので、それより前に届いていれば OK）。

> リスト変数をテキストに差し込むと1行ずつ展開されます。`- ` や `[ ]` が付いていても
> パーサ側で取り除くので、体裁は気にしなくて構いません。

### 4. トリガーを作る

`setupDailyTrigger` を1回実行すると、毎晩21時のトリガーが作られます。
（手動で「トリガー」画面から作っても構いません）

## 関数一覧

| 関数 | 用途 |
| --- | --- |
| `testBridge` | 疎通確認。ブリッジメールの解析結果をログ出力するだけ |
| `generateDailyNote` | 本番。ノートを生成して Drive に保存 |
| `setupDailyTrigger` | 毎晩21時のトリガーを作成（1回だけ） |
| `dedupeDailyNotes` | 同名ノートの重複をゴミ箱へ（各日付につき最新1件を残す） |

## 動作確認の順番

1. ショートカットを手動実行 → 自分宛に `DAILY-BRIDGE` メールが届くのを確認
2. `testBridge` を実行 → 予定・リマインダーが正しく取れているかログで確認
3. `generateDailyNote` を実行 → Drive にノートができるのを確認
4. `setupDailyTrigger` を実行 → 自動化

## 仕様メモ

- **同名ファイルは上書き**します。1日に複数回実行してもファイルは増えません
  （以前の重複はこの仕様が無かったことが原因と思われます）。
- **Claude 呼び出しが失敗してもノート生成は止まりません**。API エラー・キー未設定・
  応答拒否のいずれもログに記録し、該当セクションを空にして続行します。
- モデルは `claude-opus-5`、`effort` は `low` 固定です。Apps Script の `UrlFetchApp` は
  60秒程度でタイムアウトするため、深く考えさせない設定にしています。
  タイムアウトが起きる場合は `CONFIG.MODEL` を `claude-haiku-4-5` に下げてください。
- メール本文は各1通あたり先頭300文字だけを送ります（トークン節約と情報量のバランス）。

## 復元できなかった点

元スクリプトは削除済みで参照できないため、以下は出力結果からの推定です。

- 「今日のひとこと」やメール仕分けの元プロンプト（本実装は同等の出力を狙った再設計）
- 元がどの LLM を使っていたか（本実装は Claude）
- カレンダーの表示整形（元は勤務先名を含む独自表記だった可能性あり）
